# NeoDots design

A visitor selects a real pet from Petdex, supplies a short personality, and places it on a shared isometric island. A server-owned turn chooses an action with the OpenAI Decisions API (originally approach, wave and explore; now also the venue stations and messages described in `docs/pet-actions.md`); all browsers see the resulting event and can inspect its choice and confidence. The product records recent events, not simulated long-term memories. The preferred runtime is Three.js with Supabase persistence; a Node server protects service credentials and calls the Decisions API. A single instance controls turns for the hackathon. The app must surface provider failures, never label a simulated result as AI, and bound user input and request volume. Petdex asset provenance and image rights must be checked before distributing assets. The island uses a simple venue-inspired visual until a Blender asset is ready. One generated visual is part of the demo once assets and access are available. Verify a real package and its sprite animation layout, two-browser state, provider errors, secret exclusion and a complete demo before claiming success.
